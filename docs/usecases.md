# حالات الاستخدام (Use Cases) لمشروع issues_tracking

يهدف هذا المستند إلى توضيح كافة حالات الاستخدام والجهات الفاعلة (Actors) في نظام `issues_tracking` المستوحى من YouTrack.

## 👥 الجهات الفاعلة (Actors)

1. **المدير (Admin):** يتحكم في إعدادات النظام بالكامل، إدارة المستخدمين، الأدوار، والصلاحيات، وإدارة المشاريع بشكل عام.
2. **مدير المشروع (Project Manager):** يدير مشاريع محددة، ويتحكم في إعداداتها، دورات العمل (Workflows)، الحقول المخصصة، ويتابع سير العمل (Agile/Kanban Boards).
3. **المطور/الموظف (Developer/Assignee):** يستقبل المهام، يغير حالتها (State)، يضيف تعليقات، يسجل الوقت المستغرق (Time Tracking).
4. **المُبلّغ (Reporter/User):** ينشئ المشاكل (Issues)، يتابع حالتها، ويضيف تعليقات أو مرفقات.
5. **الضيف (Guest):** (اختياري حسب الصلاحيات) يمكنه فقط استعراض المشاريع أو المهام العامة دون القدرة على التعديل أو الإضافة.

## 📋 حالات الاستخدام الرئيسية (Primary Use Cases)

### 1. إدارة المستخدمين والصلاحيات (User & Role Management)
*   **تسجيل الدخول / إنشاء حساب (Login/Register):** عبر البريد الإلكتروني، أو مزودي خدمة الطرف الثالث (OAuth).
*   **إدارة الأدوار (Role Management):** تعيين أدوار للمستخدمين على مستوى النظام أو مستوى المشروع.
*   **تعديل الملف الشخصي:** تغيير الصورة، الإعدادات، والإشعارات.

### 2. إدارة المشاريع (Project Management)
*   **إنشاء مشروع جديد:** تحديد مفتاح المشروع (Project Key)، الاسم، والوصف.
*   **إدارة أعضاء المشروع:** إضافة/إزالة المستخدمين وتحديد أدوارهم داخل المشروع.
*   **إعدادات سير العمل (Workflows):** تحديد الحالات الممكنة للمشكلة (مثل: Open -> In Progress -> Review -> Resolved).
*   **الحقول المخصصة (Custom Fields):** إضافة حقول جديدة للمشروع (مثل: مستوى الخطورة، بيئة التشغيل).

### 3. إدارة المشاكل والمهام (Issue Management)
*   **إنشاء مشكلة (Create Issue):** إدخال العنوان، الوصف (Markdown)، تحديد المشروع، وتعيين الحقول الأولية.
*   **تحديث المشكلة (Update Issue):** تغيير الحالة (State Change)، الأولوية، أو المعين له (Assignee).
*   **البحث والتصفية المتقدمة (Advanced Search & Filtering):** استخدام استعلامات مركبة (مثل: `project: ISSUES assignee: me state: open`).
*   **تتبع الوقت (Time Tracking):** إدخال الوقت المقدر (Estimated) والوقت الفعلي المستغرق (Spent).
*   **العلاقات (Issue Links):** ربط مشكلة بأخرى (مثال: "يعتمد على"، "نسخة مكررة من").

### 4. التعليقات والمرفقات (Comments & Attachments)
*   **إضافة تعليق:** دعم Markdown وإمكانية الإشارة لمستخدمين آخرين (`@mention`).
*   **إرفاق ملفات:** رفع صور، مستندات، أو مقاطع فيديو.
*   **تعديل/حذف تعليق:** بناءً على الصلاحيات.

### 5. لوحات العمل (Agile/Kanban Boards)
*   **إنشاء لوحة عمل:** ربط اللوحة بمشروع أو استعلام محدد.
*   **السحب والإفلات (Drag & Drop):** نقل المهام بين الأعمدة (الحالات) أو الصفوف (Swimlanes).
*   **إدارة فترات العمل (Sprints):** إنشاء Sprint جديد، وإضافة مهام إليه.

### 6. الإشعارات والتتبع (Notifications & Activity Stream)
*   **تلقي إشعارات:** عند الإشارة في تعليق، أو عند تعيين مهمة، أو تغيير حالة مهمة متابعة.
*   **سجل النشاطات (Activity Stream):** عرض تاريخ التغييرات على المهمة (من غيّر الحالة ومتى).

## 🔄 سيناريو تدفق عمل نموذجي (Typical Workflow Scenario)
1. **Reporter** يقوم بإنشاء مشكلة `Bug` جديدة ويصف المشكلة.
2. النظام يرسل **Notification** لـ **Project Manager**.
3. **Project Manager** يعيّن المشكلة (Assign) إلى **Developer**.
4. **Developer** يتلقى إشعاراً، ويغير حالة المشكلة إلى `In Progress`.
5. يقوم **Developer** بإصلاح المشكلة، ويرفع التزاماً (Commit)، ثم يغير الحالة إلى `Fixed` ويسجل الوقت المستغرق.
6. **Reporter** يتم إشعاره ويتأكد من الإصلاح.
