# مهارة إنشاء ميزة جديدة (Create Feature)

استخدم هذه المهارة عند الرغبة في إضافة ميزة (Feature) جديدة للتطبيق. يجب الالتزام بالتقسيم الطبقي والخطوات الإجرائية التالية لضمان جودة الكود واتساق النظام.

## 💡 متى وكيف تطلب استخدام هذه المهارة؟
*   **متى؟**: عندما تطلب إضافة وظيفة جديدة كلياً للمشروع (مثل: نظام مبيعات، إعدادات، تقارير).
*   **كيف؟**: اطلب ببساطة "أريد إضافة ميزة [اسم الميزة]" وسأقوم بتطبيق هذه المهارة لضمان هيكلة صحيحة ونظيفة.

## 🎯 الحاجة لهذه المهارة
تضمن هذه المهارة فصل المسؤوليات (Separation of Concerns) وسهولة الاختبار (Testability) والتوسع (Scalability) للمشروع، مما يمنع تحول الكود إلى "كتلة واحدة" (Monolith) يصعب صيانتها.

## 📂 الهيكل والمعايير التقنية
يجب الالتزام الكامل بالمعمارية النظيفة لضمان توحيد المجلدات وتدفق البيانات.

### خطوات العمل الإجرائية المتسلسلة:

#### 1. تعريف الـ Entities (Defining Entities)
*   تحديد ما هي الـ Entities التي سيتم تعريفها وبناؤها للميزة.
*   بناء كل Entity باستخدام سير العمل: [إضافة كائن جديد (Entity)](../../workflows/add_entity.md).

#### 2. تعريف الـ Models (Defining Models)
*   تحديد ما هي الـ Models التي سيتم بناؤها (عادة موديل لكل Entity).
*   بناء كل Model باستخدام سير العمل: [إضافة موديل (Model)](../../workflows/add_model.md).

#### 3. واجهات مصادر البيانات (DataSources Interfaces)
*   تعريف الواجهات (Abstractions) لمصادر البيانات.
*   بناء الواجهات باستخدام سير العمل: [إضافة واجهة مصدر بيانات](../../workflows/add_data_source_interface.md).

#### 4. تنفيذ مصادر البيانات (DataSources Implementations)
*   كتابة التنفيذ الفعلي لمصادر البيانات (SQLite, API, إلخ).
*   بناء التنفيذ باستخدام سير العمل: [إضافة تنفيذ لمصدر بيانات](../../workflows/add_data_source_implementation.md).
*   **⚠️ قاعدة صارمة**: الالتزام بـ [إدارة SQLite3](../../skills/sqlite3_management/SKILL.md) عند التعامل مع البيانات المحلية.

#### 5. واجهات المستودعات (Repositories Interfaces)
*   تعريف العقود (Contracts) التي تربط بين طبقة الـ Data والـ Domain.
*   بناء الواجهات باستخدام سير العمل: [إضافة واجهة مستودع (Repository Interface)](../../workflows/add_repository_interface.md).

#### 6. تنفيذ المستودعات (Repositories Implementations)
*   كتابة المنطق الذي يربط مصادر البيانات بالمستودعات.
*   بناء التنفيذ باستخدام سير العمل: [إضافة تنفيذ لمستودع (Repository Implementation)](../../workflows/add_repository_implementation.md).

#### 7. حالات الاستخدام (Use Cases)
*   بناء المنطق البرمجي المستقل (Business Logic) لكل عملية.
*   بناء حالات الاستخدام باستخدام سير العمل: [إضافة حالة استخدام (Use Case)](../../workflows/add_use_case.md).
*   **⚠️ قاعدة صارمة**: الالتزام بحقن حالات الاستخدام في إدارة الحالة وعدم استدعاء المستودعات مباشرة.

#### 8. بناء صفحات الواجهات (Building UI Pages)
*   تحديد ما هي الواجهات التي سيتم بناؤها للميزة.
*   البدء في بناء كل صفحة بانسجام كما هو مفصل في مهارة: [بناء صفحة واجهة مستخدم (UI Page)](../ui_page/SKILL.md).

#### 9. طبقة الفحص (Testing Layer)
بعد الانتهاء من بناء الصفحات والمنطق، **يجب إجبارياً** إنشاء ملفات الفحص التالية:
*   **فحص الوحدات (Unit Tests)**: للمنطق البرمجي وحالات الاستخدام. الالتزام بـ [Unit Test](../../skills/unit_test/SKILL.md).
*   **فحص الواجهات (Widget Tests)**: للمكونات المرئية والتفاعل معها. الالتزام بـ [Widget Test](../../skills/widget_test/SKILL.md).
*   **فحص التكامل (Integration Tests)**: لضمان عمل التدفق بالكامل. الالتزام بـ [Integration Test](../../skills/integration_test/SKILL.md).



## ⚠️ مبادئ هامة
*   اعتمد على **الحقن البرمجي (Dependency Injection)** عبر `GetIt` وتسجيل كافة المكونات في الـ `Injector` الخاص بالميزة.
*   استخدم `fpdart` ومعالجة الأخطاء عبر `Either` لضمان عدم توقف التطبيق عند حدوث خطأ.
*   لا تضع أي منطق برمجي (Business Logic) داخل الـ Widgets، اجعلها للعرض فقط.
