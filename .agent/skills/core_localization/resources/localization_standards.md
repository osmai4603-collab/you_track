# معايير وقواعد الترجمة (Localization Standards)

تحدد هذه الوثيقة القواعد الصارمة لإدارة النصوص في المشروع لضمان الجودة والاحترافية.

## 1. تسمية المفاتيح (Key Naming)
*   **Lower Camel Case**: جميع المفاتيح تبدأ بحرف صغير (مثال: `errorMessage`).
*   **Semantic Names**: الأسماء يجب أن تصف محتوى النص وليس مكانه.
    *   ❌ `topTitle`
    *   ✅ `brandSelectionTitle`
*   **Prefixing**: يمكن استخدام بادئات لتنظيم المفاتيح في المشاريع الكبيرة:
    *   `auth...`: للمصادقة.
    *   `error...`: لرسائل الخطأ.
    *   `msg...`: للرسائل التنبيهية.

## 2. الأوصاف (Descriptions)
*   يجب إضافة `@key` لكل نص في ملف `app_en.arb`.
*   يجب أن يشرح الوصف سياق النص (مثلاً: "تظهر في زر الحفظ في نهاية الصفحة").

## 3. التعامل مع الجمع والمذكر/المؤنث (Pluralization & Gender)
استخدم ميزات `intl` المدمجة في الـ ARB للتعامل مع حالات الجمع:

```json
{
  "itemCount": "{count, plural, =0{No items} =1{One item} other{{count} items}}",
  "@itemCount": {
    "placeholders": {
      "count": {
        "type": "num"
      }
    }
  }
}
```

## 4. المفاتيح الشائعة (Common Global Keys)
تستخدم هذه المفاتيح بشكل متكرر في كامل التطبيق ويجب توحيدها:
*   `save`: حفظ
*   `cancel`: إلغاء
*   `delete`: حذف
*   `edit`: تعديل
*   `next`: التالي
*   `back`: رجوع
*   `errorOccurred`: حدث خطأ غير متوقع
*   `retry`: إعادة المحاولة

## 5. المحاذير البرمجية (Programming Caveats)
*   **منع الفراغات**: لا تترك فراغات في بداية أو نهاية النص داخل الـ ARB؛ استخدم `Padding` في الـ UI للتحكم في المسافات.
*   **رموز السطر الجديد**: تجنب استخدام `\n` إلا للضرورة القصوى؛ يفضل ترك المتصفح/التطبيق يعالج التفاف النص (Text Wrapping).
